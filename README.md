# HR automation — Telegram-бот для подбора персонала

Бот — HR-ассистент в Telegram: с ним общаются обычным текстом, без команд и жёсткого
сценария. Внутри работает LangChain-агент (GPT, `gpt-4o-mini`) с набором инструментов
для работы с вакансиями и кандидатами в Supabase.

## Возможности

Никаких строгих шагов — просто пишите, что нужно, например:

- «Создай вакансию Python-разработчик: нужен опыт с FastAPI от 2 лет...» — создаёт вакансию.
- «Покажи открытые вакансии» / «Покажи кандидатов по вакансии бухгалтер».
- Пришлите файл резюме (`.pdf` / `.docx`) или просто текст — бот сам разберётся,
  к какой вакансии его отнести (по контексту переписки, или уточнит вопросом),
  оценит через GPT и пришлёт балл 0–100, сильные стороны, пробелы и рекомендацию,
  с кнопками ✅ Пригласить / 🕐 Отложить / ❌ Отказать.
- «Отклони кандидата Иванову» / «Пригласи Петрова» — меняет статус по имени, без id.
- Понимает голосовые сообщения (распознаёт через Whisper и отвечает на смысл сказанного),
  пересланные сообщения (например, пересланное резюме кандидата или текст вакансии —
  бот сам поймёт, что это, и предложит подходящее действие) и ответы-цитаты на
  предыдущие сообщения бота (можно ответить на карточку вакансии/кандидата, не
  выискивая её id вручную).

Команды: `/start`/`/help` — краткая справка, `/reset` — забыть контекст текущего диалога
(на случай, если беседа зашла не туда).

Доступ к боту ограничен списком Telegram id и/или username (`ALLOWED_TELEGRAM_IDS`,
`ALLOWED_TELEGRAM_USERNAMES`).

Данные хранятся в Supabase (проект `hr-automation`): `vacancies`, `candidates` и
`chat_sessions` (память диалога — история переписки и ещё не оценённое загруженное
резюме, переживает перезапуск бота). RLS включён — доступ только через service-role
ключ бота.

## Настройка

### 1. Telegram-бот

1. Напишите [@BotFather](https://t.me/BotFather), команда `/newbot`, следуйте инструкциям.
2. Скопируйте выданный токен — это `TELEGRAM_BOT_TOKEN`.
3. Разрешите доступ нужным HR — двумя способами, можно вместе:
   - по id: узнать свой id можно у [@userinfobot](https://t.me/userinfobot), указать в
     `ALLOWED_TELEGRAM_IDS` (несколько — через запятую);
   - по username: указать в `ALLOWED_TELEGRAM_USERNAMES` (с `@` или без, несколько —
     через запятую), например `ivan_hr,@petrova_hr`. Работает только если у человека
     вообще есть публичный username в Telegram (Settings → Username). Учтите: username
     можно сменить или освободить — если это важно, надёжнее указывать id.

### 2. OpenAI API

Получите ключ на [platform.openai.com](https://platform.openai.com/api-keys) — это `OPENAI_API_KEY`.
Бот использует модель `gpt-4o-mini`.

### 3. Supabase

Проект `hr-automation` уже создан:

- `SUPABASE_URL` = `https://pdzteujalaovgxtsjsaq.supabase.co`
- `SUPABASE_SERVICE_KEY` — зайдите в [Supabase Dashboard](https://supabase.com/dashboard/project/pdzteujalaovgxtsjsaq/settings/api-keys),
  раздел **Project Settings → API**, скопируйте **service_role** ключ (не anon/publishable —
  боту нужен полный доступ на запись, а RLS в таблицах включён и закрывает доступ для anon-ключа).

  Держите этот ключ в секрете: он даёт полный доступ к базе в обход RLS.

### 4. Переменные окружения

Скопируйте `.env.example` в `.env` и заполните значения:

```
cp .env.example .env
```

### 5. Локальный запуск

```
pip install -r requirements.txt
python -m bot.main
```

Бот запустится в режиме long polling — держите процесс запущенным, пока тестируете.

## Деплой на Render (круглосуточная работа)

1. Залейте проект в Git-репозиторий (GitHub/GitLab).
2. В Render создайте новый **Blueprint** из репозитория — он подхватит `render.yaml`
   и создаст сервис `hr-automation-bot` типа **Background Worker**.
   (Можно и вручную: New → Background Worker, build command `pip install -r requirements.txt`,
   start command `python -m bot.main`.)
3. В настройках сервиса на Render добавьте переменные окружения:
   `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`,
   `ALLOWED_TELEGRAM_IDS`, `ALLOWED_TELEGRAM_USERNAMES`.
4. Задеплойте — бот будет работать 24/7 и опрашивать Telegram на новые сообщения.

## Структура проекта

```
bot/
  main.py          точка входа, регистрация хендлеров
  config.py        загрузка переменных окружения
  auth.py          ограничение доступа по Telegram id
  agent.py         LangChain-агент: системный промпт, инструменты, память диалога
  db.py            запросы к Supabase (вакансии, кандидаты, сессии чатов)
  llm.py           оценка резюме через GPT (вызывается инструментом агента)
  parsing.py       извлечение текста из .pdf/.docx/.txt
  transcription.py распознавание голосовых сообщений через Whisper (OpenAI)
  handlers/
    common.py      /start, /help, /reset, текст, документы, голосовые -> agent.py
    candidates.py  кнопки ✅/🕐/❌ после оценки кандидата
supabase/
  schema.sql       справочная копия схемы БД (уже применена к проекту)
render.yaml        описание Render Background Worker
```

## Известные ограничения

- Резюме принимаются в форматах `.pdf`, `.docx`, как текст или голосовое сообщение;
  отсканированные PDF без текстового слоя не распознаются (нет OCR).
- Максимальная длина текста резюме, отправляемого модели — 20 000 символов.
- Пересланный или голосовой текст распознаётся как «резюме для оценки», только если
  сообщение переслано (форвард) или достаточно длинное (от ~200 символов) — короткие
  реплики так не обрабатываются, чтобы не путать обычные команды с резюме. Если бот
  не подхватил текст как резюме, можно прислать его файлом или явно попросить оценить.
- Если пользователь отвечает (цитирует) сообщение с файлом/голосовым, а не текстом —
  бот видит только факт цитаты и тип вложения, а не содержимое исходного файла заново.
- Полноценная проверка бота (реальные сообщения в Telegram) требует настоящих
  `TELEGRAM_BOT_TOKEN` и `OPENAI_API_KEY` — без них проверялась только корректность
  импорта и логики кода.
